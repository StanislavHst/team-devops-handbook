# Шаблон README для консольної утиліти

Цей документ описує, з яких розділів складається README консольної утиліти,
що писати в кожному з них і як перевірити, що розділ заповнено.

## 1. Коли використовувати

Шаблон потрібен для будь-якої програми, яку запускають із терміналу: скрипта,
інструмента командного рядка, обгортки над іншою утилітою. Для бібліотек і
вебзастосунків він не підходить.

## 2. Шаблон

Скопіюйте вміст блоку в `README.md` своєї утиліти й заповніть кожен розділ.
Якщо розділ не стосується утиліти, не видаляйте його: напишіть
`Не застосовується` і одним реченням поясніть чому.

````markdown
# <назва утиліти>

## Призначення

<Одне-два речення: що утиліта робить і для кого.>

## Вимоги

- ОС: <Linux / macOS / Windows>
- Залежності та мінімальні версії: <...>

## Встановлення

<Команди, після яких утиліту можна запустити.>

## Запуск

```text
<утиліта> [параметри] <обов'язковий аргумент>
```

## Параметри

| Параметр       | Значення за замовчуванням | Опис             |
| -------------- | ------------------------- | ---------------- |
| `-h`, `--help` | —                         | Показати довідку |

## Вхід і вихід

- Читає: <аргументи, файли, stdin>
- Пише в stdout: <що саме>
- Пише в stderr: <повідомлення про помилки, прогрес>

## Змінні середовища

| Змінна   | Призначення |
| -------- | ----------- |
| `<ІМ'Я>` | <...>       |

## Файли конфігурації

<Шляхи до файлів, порядок пошуку, формат.>

## Коди виходу

| Код | Значення                                                         |
| --- | ---------------------------------------------------------------- |
| 0   | Успіх                                                            |
| 1   | <Загальна помилка>                                               |
| 2   | <Неправильне використання: невідомий параметр, бракує аргументу> |

## Приклад виводу

<Реальна команда і реальний вивід, скопійований із терміналу.>

## Безпека

<Що не можна передавати в аргументах, які параметри знижують захист.>

## Обмеження

<Чого утиліта не вміє, відомі помилки, непідтримувані платформи.>

## Див. також

<Споріднені утиліти та посилання на документацію.>

## Ліцензія

<Назва ліцензії.>
````

## 3. Що писати в кожному розділі

| Розділ             | Що має бути                                                       | Чого не писати                             |
| ------------------ | ----------------------------------------------------------------- | ------------------------------------------ |
| Призначення        | Що утиліта робить, одним-двома реченнями                          | Історію проєкту, рекламні фрази            |
| Вимоги             | ОС, залежності, мінімальні версії числами                         | «Нова версія Python» без номера            |
| Встановлення       | Команди, які можна скопіювати й виконати                          | Кроки без команд («встановіть залежності») |
| Запуск             | Синтаксис із позначенням обов'язкових і необов'язкових аргументів | Приклади без пояснення                     |
| Параметри          | Усі параметри з `--help` і значення за замовчуванням              | Параметри, яких немає в програмі           |
| Вхід і вихід       | Звідки утиліта читає, куди пише, що йде в stdout, а що в stderr   | «Виводить результат»                       |
| Змінні середовища  | Усі змінні, які утиліта читає                                     | Змінні, які вона не використовує           |
| Файли конфігурації | Шляхи, порядок пошуку, формат                                     | Файли, які утиліта лише створює            |
| Коди виходу        | Кожен код, який утиліта може повернути                            | Лише 0 і 1 без пояснень                    |
| Приклад виводу     | Справжній вивід справжньої команди                                | Вигаданий або «приблизний» вивід           |
| Безпека            | Де можуть витекти секрети, які параметри знижують захист          | Загальні поради про безпеку                |
| Обмеження          | Що утиліта не вміє                                                | Плани на майбутнє                          |
| Див. також         | Споріднені утиліти, документація                                  | Посилання, які ви не відкривали            |
| Ліцензія           | Назва ліцензії                                                    | —                                          |

## 4. Приклад заповнення: `curl`

Приклад показує, як виглядає заповнений шаблон. Версія в прикладі:
`curl 8.5.0`.

````markdown
# curl

## Призначення

Консольна утиліта для передачі даних за URL. Підтримує HTTP, HTTPS, FTP та інші
протоколи. Використовується для завантаження файлів, перевірки API та
діагностики вебсерверів.

## Вимоги

- ОС: Linux, macOS, Windows 10+
- Залежності: бібліотека TLS (OpenSSL, GnuTLS або інша, залежно від збірки)
- curl 8.22.0 libcurl/8.22.0 OpenSSL/3.6.4 zlib/1.3.2 brotli/1.2.0 zstd/1.5.7 libidn2/2.3.8 libpsl/0.21.5 libssh2/1.11.1 nghttp2/1.70.0 ngtcp2/1.25.0 nghttp3/1.18.0 mit-krb5/1.22.2

## Встановлення

```bash
# Arch Linux
sudo pacman -S curl

# Debian / Ubuntu
sudo apt install curl
```

## Запуск

```text
curl [options / URLs]
```

URL обов'язковий. Без нього curl завершується з кодом 2.

## Параметри

Лише найуживаніші. Повний перелік: `man curl` або `curl --help all`.

| Параметр         | Значення за замовчуванням | Опис                                                  |
| ---------------- | ------------------------- | ----------------------------------------------------- |
| `-o <файл>`      | stdout                    | Записати тіло відповіді у файл                        |
| `-O`             | вимкнено                  | Зберегти файл під іменем із URL                       |
| `-L`             | вимкнено                  | Слідувати за перенаправленнями                        |
| `-s`             | вимкнено                  | Не показувати індикатор прогресу й повідомлення       |
| `-S`             | вимкнено                  | Разом із `-s` показувати помилки                      |
| `-f`             | вимкнено                  | Завершуватися з кодом 22 на HTTP-відповіді 400 і вище |
| `-I`             | вимкнено                  | Запитати лише заголовки (метод HEAD)                  |
| `-H <заголовок>` | —                         | Додати HTTP-заголовок                                 |
| `-d <дані>`      | —                         | Надіслати дані методом POST                           |
| `--max-time <с>` | без обмеження             | Загальний ліміт часу виконання                        |

## Вхід і вихід

- Читає: URL з аргументів, дані з `-d @файл` або `-d @-` (stdin).
- Пише в stdout: тіло відповіді, якщо не вказано `-o`.
- Пише в stderr: індикатор прогресу та повідомлення про помилки.

Тому `curl URL > файл` зберігає лише тіло відповіді, а індикатор прогресу
лишається в терміналі.

## Змінні середовища

| Змінна                                   | Призначення                                |
| ---------------------------------------- | ------------------------------------------ |
| `http_proxy`, `https_proxy`, `all_proxy` | Проксі-сервер для відповідного протоколу   |
| `no_proxy`                               | Хости, для яких проксі не використовується |
| `CURL_CA_BUNDLE`                         | Шлях до власного набору сертифікатів CA    |

## Файли конфігурації

- `~/.curlrc`: параметри, які застосовуються до кожного запуску.
- `~/.netrc`: логіни й паролі для хостів (вмикається параметром `-n`).

## Коди виходу

Повний перелік: розділ EXIT CODES у `man curl`.

| Код | Значення                                       |
| --- | ---------------------------------------------- |
| 0   | Успіх                                          |
| 2   | Помилка ініціалізації, зокрема запуск без URL  |
| 3   | Некоректний URL                                |
| 6   | Не вдалося визначити адресу хоста (DNS)        |
| 7   | Не вдалося підключитися до хоста               |
| 22  | HTTP-помилка (лише з `-f`)                     |
| 28  | Перевищено час очікування                      |
| 37  | Не вдалося відкрити локальний файл (`file://`) |
| 60  | Сертифікат сервера не пройшов перевірку        |

## Приклад виводу

```console
$ curl
curl: try 'curl --help' or 'curl --manual' for more information
$ echo $?
2

$ curl -sS file:///nonexistent
curl: (37) Couldn't open file /nonexistent
$ echo $?
37
```

## Безпека

- Не передавайте пароль у `-u user:password`: його видно в `ps` та в історії
  оболонки. Використовуйте `~/.netrc` із правами `600`.
- `-k` (`--insecure`) вимикає перевірку сертифіката. Не використовуйте його
  поза тестовим середовищем.

## Обмеження

- Без `-L` не слідує за перенаправленнями: відповідь 301 повертається як є.
- Без `-f` HTTP-помилки (404, 500) не дають ненульового коду виходу.
- Не виконує JavaScript, тому сторінки, що будуються в браузері, отримуються
  без вмісту.

## Див. також

- `man curl`, <https://curl.se/docs/>
- `wget`: схожа утиліта для завантаження файлів

## Ліцензія

curl license (MIT-подібна).
````

## 5. Результат перевірки шаблону на `curl`

Шаблон заповнено для `curl` і порівняно з `man curl`. Мінімальний перелік
(призначення, вимоги, запуск, параметри, коди виходу, приклад виводу,
обмеження) не охоплює такого:

| Доданий розділ       | Чому його бракувало                                                            | Де знайдено в `man curl` |
| -------------------- | ------------------------------------------------------------------------------ | ------------------------ |
| Змінні середовища    | Проксі й CA налаштовуються лише змінними, таблиця параметрів цього не покриває | ENVIRONMENT              |
| Файли конфігурації   | `~/.curlrc` змінює поведінку без жодного параметра в командному рядку          | FILES                    |
| Вхід і вихід         | Різниця між stdout і stderr визначає, як утиліту використовувати в пайпах      | OUTPUT, PROGRESS METER   |
| Безпека              | Пароль у `-u` потрапляє в `ps` та історію оболонки                             | опис параметра `-u`      |
| Встановлення         | Мінімальний перелік не відповідає на питання «як це поставити»                 | —                        |
| Див. також, Ліцензія | Користувач має знати про альтернативи й умови використання                     | SEE ALSO                 |
